## معرفی پروژه

سامانه حاضر برای ایجاد یک فرآیند یکپارچه جهت دریافت و نمایش داده‌های اقتصادی طراحی شده است.

در این سامانه، داده‌ها از منابع مختلف دریافت شده و بسته به نوع منبع، با روش مناسب استخراج می‌شوند. داده‌های خام در لایه
`raw` پایگاه داده ذخیره شده و پس از پاک‌سازی و تبدیل، در جداول اصلی `dbo` قرار می‌گیرند.

ساختار پروژه به گونه‌ای طراحی شده است که:

- دریافت داده‌ها قابل تکرار باشد.
- داده‌های قبلی بدون نیاز به دریافت مجدد حفظ شوند.
- فرآیند به‌روزرسانی به‌صورت Incremental انجام شود.
- داده‌های خام از داده‌های نهایی جدا باشند.
- اطلاعات مربوط به منابع و شاخص‌ها در جداول Metadata نگهداری شوند.
- داشبورد بدون Hard-code شدن مشخصات شاخص‌ها، اطلاعات را از Metadata دریافت کند.
- فرآیندهای ETL به‌صورت خودکار اجرا شوند.

## دلیل انتخاب منابع

انتخاب منابع داده بر اساس چند معیار اصلی انجام شده است:

### ۱. اعتبار منبع

منابع انتخاب‌شده از مراجع شناخته‌شده و معتبر در حوزه داده‌های اقتصادی و آماری هستند.

### ۲. به‌روزرسانی مستمر

### ۴. مرجعیت

منبع باید در حوزه داده مربوطه دارای مرجعیت باشد تا داده‌های ذخیره‌شده و نمایش‌داده‌شده در سامانه از اعتبار مناسبی
برخوردار باشند.

## معماری کلی

معماری پروژه را می‌توان به شکل زیر در نظر گرفت:

```text

     │
     ▼
    ETL
     │
     ▼

     │
```

اپلیکیشن Streamlit اطلاعات مورد نیاز خود را از پایگاه داده دریافت کرده و در قالب داشبورد نمایش می‌دهد.

## فرآیند ETL

فرآیند ETL پروژه از سه مرحله اصلی تشکیل شده است:

### Extract

داده‌ها از منابع مختلف استخراج می‌شوند.

بسته به منبع، روش استخراج متفاوت است:

- API برای TGJU
- فایل Excel برای مرکز آمار ایران

### Transform

در این مرحله داده‌ها پردازش و استانداردسازی می‌شوند.

برخی عملیات انجام‌شده عبارت‌اند از:

- پاک‌سازی داده‌ها
- حذف HTML Tagهای موجود در داده‌های دریافتی
- تبدیل نوع داده‌ها
- تبدیل تاریخ‌ها
- استانداردسازی نام ستون‌ها
- تبدیل مقادیر عددی
- ایجاد ستون‌های مورد نیاز
- اتصال اطلاعات گروه‌ها به Mapping Table
- حذف داده‌های نامعتبر

### Load

داده‌ها در دو لایه ذخیره می‌شوند:

```text
Source
   │
   ▼
raw schema
   │
   ▼
dbo schema
```

لایه `raw` داده‌های نزدیک‌تر به داده اولیه منبع را نگهداری می‌کند.

لایه `dbo` شامل داده‌های پاک‌سازی‌شده و آماده استفاده در اپلیکیشن است.

---

## Incremental Load

برای جلوگیری از دریافت و ذخیره مجدد داده‌های قبلی، فرآیند ETL از Incremental Load استفاده می‌کند.

به‌صورت کلی:

```text
آخرین تاریخ موجود در Database
            │
            ▼
دریافت داده‌های جدید
            │
            ▼
          Filter
date > last_date
            │
            ▼
Insert New Records
```

در نتیجه، در اجرای بعدی تنها داده‌هایی که جدید هستند وارد پایگاه داده می‌شوند.

این روش باعث کاهش:

- زمان اجرای ETL
- تعداد درخواست‌ها به منبع
- حجم پردازش
- احتمال ایجاد رکوردهای تکراری

می‌شود.

### `dbo`

## Metadata

برای جلوگیری از Hard-code شدن اطلاعات شاخص‌ها در اپلیکیشن، مشخصات منابع و شاخص‌ها در جداول Metadata نگهداری می‌شوند.

دو جدول اصلی Metadata عبارت‌اند از:

```text
dbo.data_sources
dbo.indicator_sources
```

### `data_sources`

اطلاعات مربوط به منابع داده را نگهداری می‌کند.

اطلاعاتی مانند:

- نام منبع
- سازمان منتشرکننده
- روش دسترسی
- URL
- فرمت داده
- توضیحات

### `indicator_sources`

اطلاعات مربوط به شاخص‌ها را نگهداری می‌کند.

برای مثال:

- نام شاخص
- نام جدول
- ستون مقدار
- ستون Dimension
- تناوب انتشار
- توضیحات

این ساختار باعث شده است اپلیکیشن بتواند اطلاعات شاخص‌ها را از Database دریافت کند و وابستگی به نام‌های Hard-coded کاهش
یابد.

## داشبورد

رابط کاربری پروژه با استفاده از **Streamlit** پیاده‌سازی شده است.

نمایش روند زمانی شاخص‌ها.

- Percentage Change
- Index 100

- Ratio

## به‌روزرسانی خودکار

برای اجرای خودکار ETL از **Windows Task Scheduler** استفاده شده است.

دو Task اصلی پروژه عبارت‌اند از:

```text
ETL - Market daily
ETL - Inflation monthly
```

### ETL - Market daily

برای به‌روزرسانی داده‌های بازار و شاخص‌هایی که به‌صورت روزانه منتشر می‌شوند استفاده می‌شود.

### ETL - Inflation monthly

برای به‌روزرسانی داده‌های ماهانه تورم و CPI استفاده می‌شود.

فرآیند کلی:

```text
Windows Task Scheduler
          │
          ▼
       .bat file
          │
          ▼
       ETL Script
          │
          ▼
      SQL Server
```

## Setup Scheduler

برای ایجاد و تنظیم Taskهای مربوط به اجرای خودکار، اسکریپت‌ها و تنظیمات مربوط به Scheduler در پوشه `scripts` قرار
گرفته‌اند.

فایل مربوط به راه‌اندازی Scheduler:

```text
scripts/
└── setup_scheduler
```

این بخش برای ایجاد یا تنظیم Taskهای اجرای خودکار پروژه مورد استفاده قرار می‌گیرد.

## فایل‌های BAT

برای اجرای ETL از فایل‌های Batch ویندوز استفاده می‌شود.

یکی از نکات مهم در فایل‌های BAT استفاده از:

```bat
@echo off
cd /d "%~dp0"
```

است.

دستور:

```bat
cd /d "%~dp0"
```

باعث می‌شود مسیر کاری به مسیر خود فایل BAT تغییر کند؛ بنابراین اجرای فایل از مکان‌های مختلف، مانند Desktop یا Task
Scheduler، به مسیر پروژه وابسته به محل اجرای فعلی Command Prompt نخواهد بود.

## اصول طراحی پروژه

در طراحی پروژه تلاش شده است اصول زیر رعایت شوند:

### Separation of Concerns

وظایف مختلف از یکدیگر جدا شده‌اند:

```text
ETL
Database
Application
Automation
```

### Metadata Driven Design

اطلاعات مربوط به شاخص‌ها و منابع در Database نگهداری می‌شود تا اپلیکیشن تا حد امکان از Hard-code شدن اطلاعات جلوگیری
کند.

### Incremental Processing

داده‌های جدید به‌صورت Incremental دریافت و ذخیره می‌شوند.

### Raw / Clean Separation

داده خام از داده پردازش‌شده جدا نگهداری می‌شود.

### Reusability
